# M1.6: Drift Readability Plan (без turn-sprites)

Цель M1.6: повысить читаемость дрифта через маленькие изолированные эксперименты
(`branch-per-variant`) с быстрым плейтест-циклом.

Жесткое правило этапа:
- legacy спрайты поворота машины (`left/right`) не включаем ни в одной итерации M1.6.

## База и правила процесса

- Базовая ветка для всех `drift/*` вариантов: `main`.
- Один вариант = одна идея = минимальный дифф.
- Никаких режимов/хоткеев/переключателей в рамках вариантов.
- На вариант: 1-3 коммита.
- После каждого варианта фиксируем результат в `m_1_6_drift_readability_log.md`.

## Порядок веток

1. `drift/prep-v0-readability-baseline`
2. `drift/vis-v1-ttri-tilt`
3. `drift/cam-v1-velocity-frame`
4. `drift/fx-v1-worldspace-coherence`
5. `drift/cam-v2-lookahead`
6. `drift/cam-v3-spring-blend` (опционально: если V2/пружина дают скачки или ватность)
7. `drift/cam-v3-spring-blend` (`cam-v3.1` микро-шаг: low-speed anti-jerk, если остается редкий рывок)
8. `drift/cam-v4-speed-framing` (опционально: если нужно больше дороги на высокой скорости)

## Спека по итерациям

### 1) `prep-v0` (baseline cleanup)

Задача:
- выровнять документацию и константы, убрать мешающий легаси-шум;
- не включать turn-sprites;
- не менять поведение физики/камеры.

Ограничения:
- без новых визуальных режимов;
- без экспериментов с рендером.

### 2) `vis-v1-ttri-tilt`

Задача:
- рисовать машину как quad из 2 треугольников (`ttri`);
- дать произвольный поворот кузова;
- артефакты допустимы (это тест "может ли выглядеть приемлемо").

### 3) `cam-v1-velocity-frame`

Задача:
- ориентировать камеру по сглаженному `velocity`, а не по heading машины;
- на малой скорости иметь fallback на heading.

### 4) `fx-v1-worldspace-coherence`

Задача:
- привести skid/particles к новой системе камеры;
- устранить визуальное "плавание" эффектов при новой оси камеры.

### 5) `cam-v2-lookahead`

Задача:
- добавить `target = car_pos + normalize(velocity) * f(speed)`;
- обеспечить плавное нарастание смещения с ростом скорости;
- добавить сглаживание против дребезга.

### 6) `cam-v3-spring-blend` (опционально)

Задача:
- убрать бинарный fallback `velocity -> heading` и заменить на непрерывный blend;
- сохранить инерционное догоняние (spring), но без ощущения "ватности".

Критерий включения:
- делать только после фидбека, что V2 по идее правильный, но движение слишком резкое.

### 7) `cam-v3.1` low-speed anti-jerk (микрофикс)

Задача:
- точечно убрать редкий резкий поворот камеры в связке "дрифт -> почти остановка -> отпускание ручника";
- добавить ограничение резкого поворота цели камеры в low-speed зоне;
- не трогать остальную логику cam-v3 и не менять physics/fx.

### 8) `cam-v4-speed-framing` (опционально)

Задача:
- на высокой скорости показывать больше дороги впереди за счет speed-based экранного смещения;
- не менять физику и не смешивать с turn-sprites/legacy логикой.

## Публичные изменения интерфейсов/типов

1. `DriveLogic`: read-only доступ к world velocity (`vx`, `vy`) для камеры/рендера.
2. `TopdownProjector`: разделение `camera pose` и `car pose`.
3. `DriveTuning` + `data/tuning/drive/*`: параметры camera-by-velocity/lookahead/spring.
4. `core/sprites.py`: legacy turn-sprites остаются как наследие и не используются в M1.6 runtime-пути.

## Тест-кейсы для каждого варианта

1. Разгон по прямой.
2. Поворот на скорости.
3. Дуга с ручником/дрифтом.
4. Замедление до остановки.
5. Серия S-поворотов.

## Чеклист фидбека после каждого варианта

1. Стало ли проще читать траекторию движения?
2. Не стало ли сложнее управлять (ориентация/контроль)?
3. Есть ли дерганье на малой скорости?
4. Эффект слишком слабый или слишком сильный?
5. Для `ttri`: терпимы ли артефакты и на каких углах хуже всего?

## Notes

- План может уточняться по результатам каждого плейтеста.
- Изменения из следующих итераций не смешивать в текущую ветку.
