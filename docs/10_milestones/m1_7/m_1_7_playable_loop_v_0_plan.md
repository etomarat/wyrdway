# M1.7 — Playable Loop v0 (Route + Return)

**Цель:** превратить текущие «заезды до конца HP/Fuel» в минимальную игровую петлю с выбором награды, POI-лутом, возвратом по той же дороге и ремонтом в гараже.

## Метаданные
- **Файл плана:** `m_1_7_playable_loop_v0_plan.md`
- **Ветка:** `m1.7-playable-loop-v0`
- **Статус базового вождения (M1.6):** ✅ уже в `master` (камера/FX/feel зафиксированы)

---

## Решения (зафиксировано) ✅
- **Лут на карте:** вариант **A** — при выборе узла генерируем награду и **сохраняем** (то, что показали, то и выдаём).
- **POI-лут:** только на POI. Пока типы: `scrap`, `fuel`.
- **Fuel-награда:** применяется **сразу в бак**.
- **Return:** едем «как обычно снизу вверх», но используем **разворот геометрии трассы** (та же дорога в обратном порядке).
- **На return:** **дорога и ускорители те же**, а **препятствий/аномалий нет**.
- **Fail-condition:** если кончился HP/Fuel на любой ноге — **fail**.
- **Скейлинг длины:** пока **не делаем**.
- **Цеплять POI дальше:** пока **не делаем**.
- **Boost:** работает и на outbound, и на return.

---

## Требуемые сущности данных
### SegmentPlan (минимум)
Храним в RunState, создаём при выборе следующего узла.
- `from_node_id`
- `to_node_id`
- `leg_kind`: `OUTBOUND` | `RETURN`
- `seed_base` (для базовой геометрии)
- `len_units` (фиксированная длина сегмента; пока без скейлинга)
- `rewards`: `{ scrap: int, fuel: int }` (сгенерировано на карте и сохранено)

### RouteStack
История сегментов текущего рейда:
- outbound-сегменты (сейчас будет один)
- return-сегменты (производные от outbound)

## План работ (v0)

- [x] M1.6 feel/камера/FX залиты в `master`
- [x] Правила M1.7 согласованы (см. «Решения»)

### 1) Карта: «подписанный лут»
- [x] UI: на узле отображаем `Scrap +N`, `Fuel +M`
- [x] При **подтверждении выбора узла** генерируем награду и кладём в `SegmentPlan.rewards`
- [x] Повторный показ после подтверждения берёт цифры из сохранённого `SegmentPlan`

### 2) Генерация трассы: детерминированный base layout
- [x] Разделить спавн на два слоя:
  - [x] **Base layout**: дорога + ускорители (детерминированно от `seed_base` + `len_units`)
  - [x] **Threats**: препятствия/аномалии (отдельный RNG/слой)
- [x] Гарантия: base layout **не зависит** от того, спавним мы threats или нет

### 3) Outbound → POI
- [x] При старте сегмента OUTBOUND: создаём/используем `SegmentPlan` и строим трассу (base + threats)
- [x] На достижении POI:
  - [x] выдаём `rewards.scrap` в инвентарь/счётчик рейда
  - [x] выдаём `rewards.fuel` **сразу в бак**

### 4) POI → Return (та же трасса назад)
- [x] На «Evacuate / Return»:
  - [x] создаём `SegmentPlan` для RETURN на основе исходного OUTBOUND (тот же `seed_base`, `len_units`, reversed-геометрия)
  - [x] генерим **base layout** и **разворачиваем геометрию**
  - [x] threats-слой **выключен**
  - [x] ускорители остаются (как часть base)

### 5) Fail rules
- [x] Если `hp <= 0` или `fuel <= 0` на любом сегменте — показываем экран fail и завершаем рейд

### 6) Garage: ремонт за scrap
- [x] В гараже добавить простое действие ремонта:
  - [x] стоимость в `scrap`
  - [x] увеличение `hp` до cap
  - [x] UI-кнопка/ползунок «Repair»
- [x] **Бак в гараже:** не пополняем автоматически (топливо пополняется на POI)
