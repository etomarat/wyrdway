# План ужатия `build.py` через постпроцессинг (локально)

Дата фиксации: 2026-02-09

## Цель

Уменьшить размер итогового Python-бандла TIC-80 без изменений игрового исходного кода,
чтобы не мешать параллельной разработке.

## Ограничения текущего этапа

- Правим только пайплайн сборки и постпроцессинг артефакта.
- Исходники игры в `tic80/python/**/*.py` не рефакторим под размер.
- Ничего не удаляем из "запасного" кода на будущее.
- Никаких fallback-веток: если постпроцессинг сломался, сборка считается сломанной.
- CI пока не трогаем, сначала локальная отладка.

## Baseline (на момент планирования)

- `tic80/python/build.py`: `282241` байт, `8042` строк.
- Оценка резерва за счет чистки:
- комментарии: ~`45.8 KB`
- docstring: ~`36.3 KB`
- `TYPE_CHECKING`-блоки и импорты: ~`11.2 KB`
- `__slots__`: ~`5.0 KB`
- пустые строки: ~`1.4 KB`
- Доп. резерв от сжатия отступов:
- `4 -> 2` пробела: ~`24.6 KB`
- `4 -> 1` пробел: ~`36.9 KB`

## Финальный план реализации (только постпроцессинг)

1. Добавить локальный скрипт постпроцессинга бандла (например `scripts/minify_tic80_build.py`).
2. Вход скрипта: `tic80/python/build.py`, выход: `tic80/python/build.min.py`.
3. Шаги трансформации в фиксированном порядке:
1. Сохранить TIC-80 metadata-шапку в начале файла.
   Это строки формата `# title`, `# author`, `# desc`, `# site`, `# license`, `# version`, `# script`.
2. Удалить все остальные комментарии в файле (full-line `# ...`).
3. Удалить `from typing import TYPE_CHECKING...` и блоки `if TYPE_CHECKING: ...`.
4. Удалить все docstring (module/class/function).
5. Удалить присваивания `__slots__ = ...`.
6. Сжать отступы: заменить уровень отступа с 4 пробелов на 1 пробел.
7. Удалить пустые строки.
4. Добавить проверку корректности результата:
1. Файл после постпроцессинга парсится как Python (AST parse).
2. Metadata-шапка сохранена в начале файла.
5. Встроить запуск постпроцессинга в локальный сборочный скрипт после bundler.
6. Экспорт/запуск использовать уже `build.min.py` вместо `build.py`.
7. После каждого запуска печатать отчёт:
1. размер до/после в байтах
2. экономия в байтах и процентах

## Критерии готовности этапа

- `run_tic80_python.bat build` проходит с генерацией `build.min.py`.
- Локальный запуск в TIC-80 проходит на `build.min.py`.
- Нет fallback-пути на исходный `build.py`.
- Экономия размера подтверждена отчётом постпроцессора.

## Что в техдолг (не делать сейчас)

1. Разделение `contracts` на runtime-минимум и type-only слой.
2. Профили сборки (`playtest/full`) для селективного `include(...)`.
3. Опциональная DCE/feature-паки для vendor FX (код хранить, в бандл включать профилями).
4. Перенос локально отлаженного постпроцессинга в GitHub CI.
5. Автотесты эквивалентности поведения между `build.py` и `build.min.py`.
