# Lua Migration Plan

Дата фиксации: 2026-03-14

## Цель

Проверить, даёт ли перенос игры с TIC-80 Python (PocketPy) на Lua
достаточный выигрыш по code budget, чтобы оправдать полную миграцию.

Этот документ живёт только в `tic80/lua/` и не меняет основной набор
проектной документации.

## Контекст

- Текущий Python-бандл уже близко подходит к практическому лимиту по коду.
- Переписывать всю игру на Lua сразу рискованно:
  - большой объём;
  - легко потерять темп разработки;
  - без раннего замера размера можно получить дорогой rewrite без нужного выигрыша.
- Поэтому сначала делаем не полный rewrite, а **vertical slice** на Lua.

## Решение

Миграцию на Lua вести поэтапно.

Сначала:

1. поднять Lua-пайплайн сборки и запуска;
2. перенести каркас игры;
3. перенести минимальный игровой цикл;
4. замерить итоговый размер Lua-бандла;
5. только после этого принимать решение о полном переносе.

## Почему Lua

- Это основной и самый типовой язык TIC-80.
- Он обычно компактнее Python по итоговому source budget.
- Для TIC-80 под Lua проще найти примеры, сниппеты и библиотеки.
- Lua даёт более предсказуемый рантайм, чем PocketPy, если проект уже упирается в ограничения платформы.

## Почему не брать другой язык первым

### Не брать сразу Fennel / Moonscript

- Они всё равно компилируются в Lua.
- Это добавляет ещё один слой toolchain.
- Для задачи "проверить выигрыш по размеру" проще и честнее писать Lua напрямую.

### Не брать сразу WASM

- Это уже другой класс пайплайна и отладки.
- Появляется лимит на бинарь и отдельная интеграционная сложность.
- Для быстрого сравнения с текущим Python-проектом это слишком тяжёлый путь.

## Целевой подход

### Фаза 0. Инфраструктура Lua

Сделать рядом с Python отдельный Lua-поток разработки:

- `run_tic80_lua.bat`
- `run_tic80_lua.bat build`
- `run_tic80_lua.bat dist`
- структура исходников под `tic80/lua/src`
- простой bundling/concat pipeline под Lua

Ожидаемый результат:

- Lua-код можно собирать и запускать независимо от Python-ветки.

### Фаза 1. Каркас игры

Перенести минимальный фундамент:

- boot/init
- `TIC()`
- scene manager
- scene ids
- run state / profile state
- save/load
- базовый input wrapper

Ожидаемый результат:

- Lua-проект умеет стартовать, переключать сцены и хранить состояние.

### Фаза 2. Vertical Slice

Перенести минимальный играбельный цикл:

- `MAIN_MENU`
- `GARAGE`
- `REGION_MAP`
- один упрощённый `DRIVE`
- `RESULT`

На этом этапе:

- допустимо временно упростить визуальные эффекты;
- допустимо не переносить весь дебаг/UI-комфорт;
- недопустимо ломать основную структуру loop.

Ожидаемый результат:

- в Lua можно пройти базовый loop и экспортировать картридж.

### Фаза 3. Замер бюджета

После vertical slice обязательно замерить:

- размер итогового Lua-бандла;
- сколько осталось до лимита;
- насколько дорого будет вернуть отсутствующие системы;
- какие подсистемы дают самый большой вклад в размер.

Решение после замера:

1. Если выигрыш большой, продолжаем полный перенос.
2. Если выигрыш средний, переносим только самые тяжёлые подсистемы и упрощаем scope.
3. Если выигрыш маленький, не идём в rewrite всей игры.

### Фаза 4. Полный перенос

Только если фаза 3 подтверждает смысл миграции.

Порядок переноса:

1. core state
2. scenes
3. drive systems
4. UI helpers
5. FX/vendor code
6. tuning/data tables
7. debug/perf overlay

## Что переносить не сразу

На раннем этапе не тащить один-в-один всё подряд:

- весь debug tooling;
- второстепенные overlay;
- необязательные playtest hooks;
- тяжёлые FX, если они не нужны для проверки loop;
- всё, что не влияет на сравнение размера и жизнеспособность миграции.

## Принципы переноса

- Не делать mechanical line-by-line rewrite.
- Сохранять gameplay contracts, а не Python-структуру как таковую.
- В Lua предпочитать простые таблицы и локальные модули вместо имитации Python-классов один-в-один.
- Сразу писать с оглядкой на размер итогового бандла.
- Не смешивать Python и Lua в одном runtime path.

## Критерий успеха эксперимента

Эксперимент считается успешным, если после vertical slice становится ясно, что:

- Lua даёт ощутимый выигрыш по размеру;
- базовый loop переносится без архитектурного тупика;
- дальнейший перенос не выглядит дороже, чем продолжение борьбы за байты в Python.

## Критерий отмены

Миграцию стоит остановить, если:

- выигрыш по размеру оказался небольшим;
- стоимость переноса drive/UI/FX слишком высока;
- скорость итерации в Lua ощутимо падает;
- для релизных задач дешевле урезать scope и дальше оптимизировать Python-бандл.

## Практический следующий шаг

Следующий инженерный шаг:

1. создать Lua build/run pipeline;
2. завести `tic80/lua/src`;
3. перенести `SceneManager` и минимальный boot;
4. собрать первый пустой, но модульный Lua-бандл;
5. после этого переносить vertical slice.

## Предварительная рекомендация

Идти в **Lua-first migration experiment**, а не в немедленный полный rewrite.

Это даёт:

- быстрый ответ по размеру;
- меньший риск;
- понятную точку остановки;
- возможность отказаться от полного переноса без потери всей проделанной работы.
